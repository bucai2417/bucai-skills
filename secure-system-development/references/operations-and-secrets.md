# 密钥、运维与邮件安全

代码写对了，密钥泄露或运维配置错误一样能把系统打穿。这里覆盖开发之外最常出事的几块。

## 1. 密钥管理

- 按环境隔离（生产/预发/开发），按服务隔离；一个密钥泄露不影响其他系统。
- 存放：密钥管理服务（Vault、云 KMS、SSM）或平台注入的环境变量；**不进仓库、不进镜像层、不进前端 bundle、不进日志与错误上报**。
- 前端没有秘密：JS 里的任何 key 都是公开的。必须放的（地图、统计）要在服务商侧限制 Origin、配额、权限范围。
- 轮换：定期轮换 + 离职/泄露立即轮换；保留「双密钥」过渡期。
- 泄露响应：吊销 → 评估访问记录 → 通知相关方 → 复盘入口（哪个环节泄露的）。
- 检查：CI 跑 gitleaks/trufflehog，扫描历史提交与构建产物。

## 2. 配置与多环境

- 配置与代码分离；预发环境绝不连接生产数据库/消息队列。
- 调试开关、测试后门、mock 路由、`/debug` 面板：默认关闭，生产启动时断言为关闭。
- 环境变量读取时做启动校验（缺关键项直接启动失败，而不是运行到一半才崩）。
- 配置变更要留痕、可回滚。

## 3. CI/CD 安全

- CI 凭据最小权限；优先用短期凭证（OIDC 换取云角色），不存长期 AK。
- Fork 的 PR 不注入 secrets；敏感构建在生产分支才解锁。
- 生产部署需审批 + 可追溯（谁、什么 commit、什么产物）。
- 构建产物固定、可验证（镜像 digest、SBOM），依赖缓存注意投毒。
- 部署脚本不打印环境变量；日志同样会被存档。

## 4. 容器与云

- 容器：非 root、只读根文件系统、`drop ALL` capabilities、按需 seccomp/AppArmor；镜像用最小基础镜像并固定 digest。
- 云 IAM：按角色授权、按资源前缀授权；不用根账号、不用长期 access key。
- 对象存储：默认私有；禁止 ListBucket 公开；下载走短期签名 URL；上传限制大小与类型。
- 元数据服务：从业务容器访问云元数据要限制（SSRF 主要目标就是它）。
- 网络：安全组只开必要端口；数据库/Redis/MQ 不暴露公网；管理端口走 VPN/跳板。

## 5. 邮件安全（最容易被忽略）

- 配好 SPF、DKIM、DMARC：否则别人能用你的域名发钓鱼邮件，用户和客户都会受害。
- 发信/短信接口：鉴权 + 按账号与 IP 限流 + 内容模板固定（防被当群发工具），发送记录留痕。
- 邮件里的用户输入要转义（HTML 邮件同样有 XSS 面）；链接跳转目标校验。
- 验证码邮件/短信与登录接口联动限流，否则就是轰炸机（见 `auth-and-session.md` 第 6 节）。
- 提供退订与投诉入口，保持发信域名信誉。

## 6. 日志与审计

- 结构化日志（JSON），带 `trace_id`、`user_id`、服务名、耗时；敏感字段脱敏（手机号、身份证、卡号、token、密码）。
- 日志注入：用户输入里的换行/控制字符会伪造日志行，结构化输出 + 转义。
- 审计日志单独存储、只追加、访问受控、保留期明确；业务代码不能改。
- 审计范围：登录/登出、改密、改权、导出、删除、退款、配置变更。
- 日志平台本身也要鉴权，别把「日志」做成新的泄露渠道。

## 7. 数据生命周期与隐私

- 最小化收集：不用的字段不存；表单只收必要信息。
- 保留期：明确每类数据的保留时长，到期自动清理；注销后按承诺删除或匿名化。
- 加密：传输 TLS 1.2+（禁用弱套件），静态数据加密，高敏字段字段级加密（密钥在 KMS）。
- 备份：加密、独立权限、定期恢复演练；备份同样受数据保留与访问审计约束。
- 导出/共享：审批 + 脱敏 + 水印/追踪（视敏感度）。

## 8. 监控与应急

- 安全相关指标：登录失败率与地理跳变、权限拒绝激增、异常导出、异常出站请求、依赖漏洞公告。
- 告警分级 + 值班 + 处理手册；避免告警疲劳。
- 应急流程：止血（隔离/限流/下线入口）→ 取证（保全日志与现场，先复制再清理）→ 通知（用户/客户/监管，按需）→ 修复 → 复盘与改进项跟进。
- 演练：至少做一次「密钥泄露」「数据库备份恢复」的桌面演练，别等真出事才第一次走流程。
