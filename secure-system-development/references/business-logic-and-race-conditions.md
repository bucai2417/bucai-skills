# 业务逻辑漏洞与竞态条件

扫描器扫不出这类问题：代码「能跑、没报错、没有注入」，但业务上可以被薅、被刷、被绕过。只能在设计时逐条问「如果用户不按正常流程来，会发生什么」。

## 1. 信任边界：客户端永远不掌握真相

- 价格、折扣、运费、佣金、积分兑换比例、权限等级、订单状态——全部服务端计算/确认。
- 不接受客户端传来的 `user_id`、`tenant_id`、`role`、`status`、`amount`、`is_vip`；从会话和服务端数据推导。
- 校验「值是否合理」：负数、0、超大数、精度截断、单位（元 vs 分）、时区。
- 提交前校验不够，落库前再校验一次（异步/队列路径同样要校验）。

## 2. 金额与支付

- 金额用整数分；下单金额服务端重算，与客户端展示值不一致以服务端为准（不一致直接拒绝更安全）。
- 支付回调必须：验签 → 校验金额与订单号 → 幂等（重复回调返回成功）→ 状态机校验。
- 防重放：`timestamp` + `nonce` + 签名；时间窗有限（如 5 分钟）；nonce 去重。
- 退款：累计退款 ≤ 已支付金额；部分退款逐笔记录；退款接口幂等。
- 提现/转账：限额、风控规则、必要时人工审核、双人复核。
- 日终对账：本地账与渠道账比对，差异告警 + 修复流程。

## 3. 优惠券、积分、兑换码

- 核销必须原子，不能「先查未使用，再更新」：

```sql
UPDATE coupons SET used_at = now(), order_id = $2
WHERE id = $1 AND used_at IS NULL AND user_id = $3;
-- 影响 0 行 → 已被使用或不属于该用户
```

- 兑换码：高熵、绑定用途、按 IP/账号限流尝试次数（防枚举）。
- 叠加规则写在服务端并显式建模（互斥/可叠加/优先级），不要依赖前端。
- 积分扣减与订单写入同事务，或走补偿 + 对账。
- 领券/签到/抽奖这类「每人一次」接口，用唯一索引兜底（`UNIQUE(user_id, activity_id, date)`）。

## 4. 库存与超卖

详见 `database-concurrency.md`。核心：条件更新或 Redis 预扣，绝不「查完再加锁前」有间隙；预占要有超时释放；取消/退款回滚库存要幂等（防重复回滚）。

## 5. 状态机

- 每个业务对象定义显式状态与允许的跃迁；非法跃迁直接拒绝，不要「按当前状态顺手改」。
- 回调可能乱序到达（先收到 `shipped` 再收到 `paid`）：按版本号/时间戳丢弃陈旧事件。
- 终态（已完成/已关闭/已退款）不可被迟到消息改写。

## 6. 竞态条件（TOCTOU）

「检查 → 再执行」之间被插队是所有并发 bug 的根源：

| 场景 | 错误写法 | 正确写法 |
|---|---|---|
| 注册重名 | 先 SELECT 再 INSERT | 唯一索引 + 捕获冲突 |
| 每日签到 | 先查是否已签 | `INSERT ... ON CONFLICT DO NOTHING` |
| 抢券 | 先查库存 | 条件更新扣减 |
| 任务领取 | 先查状态 | `UPDATE ... WHERE status='open'` |
| 唯一用户名 | 先查后写 | 唯一索引 |
| 余额扣减 | 读余额→判断→写 | `UPDATE ... WHERE balance >= ?` |

- 分布式锁只降低并发，**正确性靠唯一约束 + 条件更新 + 幂等**；锁失效/超时会出事。
- 乐观锁冲突要重试（次数有限），重试本身要幂等。

## 7. 限购与频控的语义

- 维度组合：用户 + 设备指纹 + IP + 支付账户；单维度都能被绕过（换 IP、换设备）。
- 限购校验必须在服务端、在事务内、在扣减同一条语句里完成，不能「先校验再下单」。
- 频控要考虑绕过：大小写、参数污染、不同接口路径、批量接口、GraphQL 别名。

## 8. 账号相关业务

- 改邮箱/手机：验证旧联系方式 + 新联系方式，通知原邮箱，设置冷却期（期间可撤销）。
- 新设备/异地登录：通知 + 二次验证；允许用户查看并撤销会话。
- 账号合并/注销：二次确认、数据归属、保留与删除策略明确。
- 找回/换绑是账号接管的高发路径，全部走 `auth-and-session.md` 的 token 规则。

## 9. 导出、批量与搜索滥用

- 导出：条数上限、分页、限流、字段白名单、审计（谁、何时、导出了多少）。
- 批量接口：单次条数上限；逐条鉴权；部分失败要明确返回。
- 搜索：查询复杂度上限、超时、防止用参数遍历全量数据。
- 反爬：必要时行为风控、验证码、签名参数；但不要把反爬做成主要安全边界。

## 10. 邀请、拉新、分享

- 邀请奖励：防自邀（同一设备/支付/IP）、防批量注册（注册频控 + 设备指纹）。
- 分享/跳转链接带签名，落地页校验来源；跳转目标走白名单（防开放重定向 + 钓鱼）。
- 奖励发放走异步 + 对账，避免超发。

## 11. 兜底：风控与审计

- 规则引擎 + 黑白名单 + 阈值告警；高风险操作人工审核。
- 所有敏感操作（改价、退款、改权限、导出、删除）留审计日志，不可被业务代码篡改。
- 定期复盘：哪些接口最常被异常调用，补规则而不是只补代码。
