## 4. STRIDE 检查表

对每个信任边界逐行问一次：

| 威胁 | 问什么 | 本项目对应措施 |
|---|---|---|
| **S**poofing 身份伪造 | 能否冒充他人身份？会话/令牌如何校验？ | |
| **T**ampering 篡改 | 请求/响应能否被改？是否有签名/校验？ | |
| **R**epudiation 抵赖 | 关键操作是否有审计日志？ | |
| **I**nformation disclosure 信息泄露 | 错误信息、日志、响应字段是否泄露？ | |
| **D**enial of service 拒绝服务 | 限流、超时、队列积压防护？ | |
| **E**levation of privilege 权限提升 | 能否越权访问他人资源/管理功能？ | |

## 5. 必填结论

设计文档必须写清这几项，缺一项就按未完成处理：

1. **认证方式**：会话 / JWT / 第三方登录；多因素策略。
2. **授权模型**：角色 → 资源 → 动作；多租户隔离方式。
3. **敏感数据**：加密方式（传输/静态/字段级）、密钥存放位置。
4. **限流策略**：按 IP / 账号 / 设备 / 接口，各自阈值。
5. **幂等键**：哪些写操作必须幂等，键的生成与存储。
6. **失败降级**：依赖不可用时如何降级，哪些操作可异步。
7. **日志与审计**：记录什么、脱敏规则、保留期。
8. **收录策略**：公开页清单 / 整站 noindex / 不适用。
9. **接口完整性**：哪些接口需要签名，时间窗与 nonce 策略。
